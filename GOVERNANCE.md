# Governance

Qairos maintainers review changes and approve releases. Security and compatibility take priority over feature count.
Public behavior changes require documentation and tests; breaking changes require an explicit version change and migration guidance.
Maintainers may reject changes that introduce shared signing keys, unsupported protection claims or unnecessary personal data collection.
Contributors retain attribution under the applicable license. The Qairos name and brand assets do not imply endorsement of a fork.
Repository permissions, branch protection and registry ownership are managed separately from source code.
